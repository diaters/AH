# 持续监控输出与送达闭环

> __状态：当前有效__
> 实现已确认的单通道任务与进程生命周期规格任务 D；定时监控 P1 单独推进。

## 工具与投递

`shell_start` 保留原有参数，新增 `notify_on_output`（默认 `false`）。开启后，stdout 的完整非空行
成为监控事件；stderr、未换行内容和静默时段不产生消息。审批展示开关与实际目标通道。
`notify_on_exit` 继续独立控制退出通知；开启输出监控时，即使关闭退出通知，也保留后台生命周期归属。

Harness 先经现有 ChannelManager 投递原始告警，再把排队和最终结果作为 `TaskNotification` 送入原 Task。
Agent 不必重复转发。排队成功与平台成功严格区分，平台不返回消息 ID 也可表示成功。
本地拒绝入队不会标为 queued；网络发送最多等待 30 秒。失败按 1、2、4 秒退避，最多三次重试，
最终失败也保留记录并通知。没有平台幂等键时，重试可能重复，不承诺恰好一次。

TUI 按本地前端接收事件确认，不冒充 IM 平台回执。没有目标通道时明确失败。

## 缓冲、顺序与身份

- 事件身份是 `(session_id, sequence)`；backend 保留未确认事件，平台终局结果后才累计确认连续前缀。
- 合并截止从首条事件计算，默认 300ms；新事件不延长截止。每会话逐批发送，不能越过待重试的前批次。
- 单行增量读取，最多保留 UTF-8 安全的 64 KiB 尾部，记录原始字节数和截断事实。
- 每会话未确认队列（含元数据计费）最多 1 MiB，溢出保留可见错误并停止会话。
- poll 单次正文总量最多 64 KiB，并在会话间轮转，慢会话不能独占 backend 读取窗口。
- 会话结束记录的 128 条淘汰上限不影响未确认事件；已确认的空队列在生产者结束后清理。
- Agent 收件箱仅保留有界监控摘要：同会话合并、最多 32 个会话、每条最多 2 KiB；合并与摘要淘汰可见，
  先前失败不会被新成功静默抹去。用户 steer 和其他后台通知不受监控摘要淘汰影响。
- 运行期 `MonitorDeliveries::recent_records` 可查询最近 128 批终局结果，记录不跨进程重启恢复。

## 任务与唤醒

任务结束后不接受新的告警投递；尚未入队事件记为终止，已入队消息可能迟到，回执始终携带旧 Task 身份，
不能唤醒同通道的新任务。后台内容不登记为用户输入或可信图片来源。

自动后台唤醒使用滚动窗口，默认每 10 秒最多 5 轮，超限自动恢复。用户 steer 不消耗也不清空窗口额度。
`Waiting(BackgroundJobs)` 可消费输出与 steer，后台工作继续存活；自然完成仍等待后台工作结束。
空闲自动结束检查真实会话、在飞执行、未完成子任务与待送达通知，不只检查通知用 OwnedJobs。

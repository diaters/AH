# 工具循环反馈与受管监控修正

> __状态：当前有效（已确认方案，已实施）__。
> 用户于 2026-10-30 确认以流量监控日志为回归场景，要求修改具备通用性。

## 问题与目标

`harness_2026-10-30_11-05-29.jsonl` 暴露出混合文字与工具响应丢失、steer 缺少实际执行状态、
一次性 shell 被用于长期监控、脚本结果与工具调用成功语义混淆的问题。
方案已在对话中评审确认；本文件记录实施契约，不新增 Task、WorkItem 或通知系统。

## 实施契约

1. 执行输出支持文字与工具并存。保留原有纯文字、纯工具响应兼容性；
   伴随工具的文字既进入同一条 Assistant 对话消息，也进入用户输出，不能触发任务完成。
   推理内容仍仅用于 provider 上下文，不作为用户文字输出。
2. steer 继续在原任务的工具结果边界处理，不中断工具、不并发创建第二个执行请求。
   接收时反馈真实等待状态与在飞工具；下次模型请求明确要求优先回应用户补充。
   状态反馈不读取 Agent 自报的进度清单作为事实。
3. 长期进程使用 `shell_start` 前台运行，持续告警使用 `notify_on_output=true`。
   stdout 只写可发送的完整非空告警行，诊断写 stderr；宿主退出时沿用 supervisor 回收契约。
   不通过 `nohup`、外部服务管理器逃离清理，也不在框架中硬编码监控脚本或环境路径。
4. 复用既有监控输出、平台回执、重试、终局失败记录与任务归属。
   脚本输出不等于发送成功，平台成功不等于用户已阅读；保留当前不跨重启恢复的边界。
5. shell 结果明确区分接口返回与命令成功，非零退出、信号终止及超时不能被报告为命令成功。
   通用结果处理不猜测任意工具 JSON；命令状态由 shell 执行层给出。
6. 监控口径、采样健康及恢复命令由场景脚本负责验证；通用工具指引要求说明单位、范围、
   采样策略并校验运行状态，不内置流量算法，也不擅自更改已运行的用户监控。

## 验收

- provider 解析：混合响应保留文字、工具 ID/参数与推理字段；纯文字及纯工具保持兼容。
- ECS 工具循环：进度文字只发一次，不提前结束；首次和后续响应均保留文字至对话历史；
  内部 `chat_with_agent` 子对话仍由父 Agent 决定对外汇报，不能因保留进度而扩大可见范围。
- steer：运行中输入沿用原 Task，回执含真实状态，补充进入下一结果边界，不打断进程。
- 监控场景：临时前台采样进程输出可控超阈值事件，经测试通道发送并获取实际回执；
  低流量、超阈值和恢复以受控输入模拟，不依赖本机网卡、公网下载或用户账号，
  不声称验证某个特定系统的网卡计数算法。
- 生命周期与失败：会话在工具返回后仍存活；终止 Task 或宿主后回收；发送重试/最终失败沿用既有测试。
- 日志：非零退出及超时有明确命令结果，不能仅依据工具接口成功认定业务成功。
- 完成后执行格式、Clippy、全量测试及文档检查；真实 QQ 验收另行明确授权。

本次修改作用于通用响应模型、路由、shell 工具契约和通道适配，不迁移本机现有 LaunchAgent、
不修改用户生成的流量脚本、也不自动发送真实 QQ 消息。流量口径与采样算法由具体业务脚本负责，
通用框架提供生命周期与可靠性边界，工具指引要求单独验证业务脚本。

## 验证记录

### 真实验收后的修正契约

2026-10-30 用户真实 provider / QQ 验收暴露恢复、重试与健康记账缺口，
并确认继续修复。以下沿用原 Task、收件箱、受管作业与运行账本边界：

- 协议历史保留真实轮次、调用 ID、参数及推理字段；仅驻留 Task 的运行时内存，
  不进入展示元数据、长期记忆或导出。旧 STM 只走文本摘要，禁止伪造工具协议。
  压缩失效运行时缓存；被中断的调用补充明确的中断结果，不能留下悬空工具 ID。
  工具参数和推理仍计入 token 成本，与派发预算共用估算；不能因禁止导出原始入参而漏算压缩阈值。
- 到期信号按任务、退避计数与 deadline 认领，消费者再次验证当前退避身份；
  重复或迟到事件不能将 Running、终态或新一轮退避改回 Ready。
- HTTP 400 / 422 归类为不可直接重试的参数错误，不触发模型降级。
- 无人值守权限拒绝留下结构化运行失败，最终文字不能把失败变为正常静默；
  保留权限边界，不全局放开 shell。正常命令探测的非零退出不自动判整次运行失败。
- 后台通知引起的解释/汇报轮次失败时，如仍有受管作业，保留作业并输出明确错误；
  用户请求的失败及显式终止仍沿用终态清理。用户新输入解除这一轮次标记。
  自动通知不覆盖用户目标；失败上下文仍留在原任务，便于后续查询和停止。
- tokenizer 进程内复用；历史预算一次计算、整组裁剪，避免同步重复构建与全量重算。

业务采样脚本仍由场景负责。受控回归覆盖恢复、权限拒绝与重复事件；
不把 mock provider / 测试通道结果宣称为真实 provider / QQ 复验。

### 修正后的受控场景

`monitor_feedback_flow` 通过生产 ECS、真实临时 shell 与测试通道执行：

1. 36 轮工具调用结束后清理工具循环，进入空闲态。
2. 临时采样文件从低流量切换到超阈值，收到平台模拟回执，自动唤醒原任务。
3. 检查恢复保留各轮真实参数及推理；模拟 provider 返回 400，验证明确提示且会话仍存活。
4. 模拟 provider 恢复，再发状态查询，验证仍是同一 Task，后台通知没有覆盖用户目标。
5. 采样恢复后仍正常投递；最后 `/finish` 回收会话。

本机相同短文本估算基准：76 次调用由约 13.63 秒降到预热后约 6.5 毫秒。
这是 tokenizer 的离线成本，不是 QQ 网络或整条告警链路的时延承诺。
真实 400 的具体拒绝字段仍需真实 provider 复验，新增协议形状诊断用于后续定位。

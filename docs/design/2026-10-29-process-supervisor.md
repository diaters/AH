# 实例级进程守护实现

> __状态：当前有效__
> 对应已确认规格的任务 B；用户任务唯一性与持续输出投递分别由任务 C、D 推进。

## 运行边界

生产 `main` 首先处理隐藏入口 `--internal-process-supervisor`，该入口不加载 dotenv、
provider、日志、通道或 TUI。正常入口先加载 dotenv 和日志，再创建独占守护器以继承环境；装配 app 后注入受管 backend，
首次驱动 ECS 前替换本地 backend。启动或握手失败直接返回错误，不降级到本地执行。

`NativeProcessBackend::supervised` 是宿主 RPC 句柄；守护器内复用本地 native 实现，
由守护器实际创建、登记、停止与回收命令。`Default` 的本地实现供守护器和既有测试使用；
自行嵌入库的宿主必须明确装配受管构造器，不能把本地实现当成异常死亡保障。

守护器与每个命令分别建立独立进程组。宿主持有专用 Unix socket lifeline 的唯一共享端点；
RPC 使用另一条 Unix socket，不复用 stdin。守护器入口立即为私有描述符设置 CLOEXEC，
其副本同样不跨 exec 继承。一次性 exec 继承宿主 stdin，交互会话创建独立输入管道。

## 并发与协议

- 启动握手具有三秒超时，协议版本为 1。
- RPC 使用长度前缀 JSON，单帧最多 4 MiB；编码期间也检查上限，超长响应返回明确错误。
- 宿主最多持有 64 个待回应请求，服务端解码队列与并发工作线程各最多 64 个。
- 长 exec、会话输入与输出读取在工作线程执行；取消由控制循环直接投递 token。
- lifeline 检测独立于 RPC 解码和工作线程；半帧、长命令或阻塞输入不能阻止 EOF 清理。
- 每次派发前再次检查 lifeline，EOF 后丢弃尚未执行的队列请求；backend 的共享启动闸门
  将已派发但尚未启动的请求与批量关闭串行化。
- 响应写入具有两秒超时；控制循环不等待工作线程持有的响应锁，协议或容量故障明确失败。

非 exec RPC 使用覆盖写锁排队、发送和等待响应的两秒绝对期限。长 exec 的完成由工具超时或取消决定，
取消发出后同样要求两秒内回应。协议错误、发送或响应超时会关闭整个实例的进程服务，
先等待该实例所有受管进程清理，再返回明确包含清理范围的错误；不会只终止单个请求。
正常业务错误（例如不存在的会话）不触发实例关闭。

服务连接异常退出后，宿主的待回应请求全部报错，新进程调用被拒绝。没有无人管理的 fallback。

## 关闭路径

显式 `shutdown()` 先封闭宿主的新请求并关闭 lifeline，等待守护器报告进程退出。
正常关闭、宿主 panic unwind、abort 或 SIGKILL 均由同一 EOF 路径进入服务端批量回收。

服务端沿用 native 共享启动闸门及批量 TERM/KILL/reap：所有命令共用一秒 TERM 宽限，
再统一强杀残留，输出 reader 共用 500ms drain 宽限；不按命令数量逐个累加。
组长回收前使用其保留的 PID 向进程组发信号，回收后不再使用旧 PGID。
客户端关闭幂等，最多等待守护器四秒；超时或异常退出明确返回失败。

生产主循环退出后先停止进程 backend，再关闭通道。装配 app 后创建的关闭 guard
在错误返回与 panic unwind 时先于 app、通道和异步运行时析构；worker clone 不延迟显式关闭。

## 独立审计日志

生产入口在 `HARNESS_LOG_DIR`（默认 `logs`）中创建
`harness_<时间>_<宿主 PID>.processes.jsonl`。守护器以同步整行追加方式写入生命周期事件，
即使宿主被 SIGKILL，仍可记录存活连接 EOF、TERM/KILL 与回收完成；不记录命令、环境变量或输出正文。
宿主也向该文件写入启动失败与连接异常事件。文件创建权限为 `0600`，同一文件的进程停止与回收事件通过 `OwnedProcess` span 直接携带
会话、任务与 Agent 身份，并保留 PID/PGID。未配置日志的库测试构造器不创建用户日志。

## 验证与限制

`tests/process_lifecycle.rs` 通过构建出的 Harness 可执行文件启动真实守护入口，
以独立测试子进程充当宿主，验证强杀、abort、panic、正常与显式关闭、独立实例、
实际父进程归属、长 exec 的取消与 EOF、超时、交互输入、受控 EOF stdin、
阻塞输入、批量关闭、启动关闭竞争与守护器故障。诊断进程在失败断言前按身份清理。

当前实测平台为 macOS。Unix 实现面向 macOS / Linux；Linux 与 Android 尚未在本轮做设备回归，
其他平台的生产入口明确报告不支持该进程守护模式。
保障范围是受管命令及留在其进程组中的普通后代，包括 `&` 和 `nohup`；
主动通过 setsid 或外部服务管理器脱离的 daemon 不在范围内。
守护器自身被强杀时不能执行回收代码，此时宿主停止接收进程工具并报告服务故障。

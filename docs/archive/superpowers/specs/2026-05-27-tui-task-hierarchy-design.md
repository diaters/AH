# TUI 任务层级显示设计

日期：2026-05-27

## 背景

当前 TUI 的 StatusPanel 以平铺列表方式显示所有任务，主任务和子任务没有视觉区分。随着任务复杂度增加，用户难以快速理解任务的层级关系和执行进度。

## 设计目标

1. 清晰区分主任务和子任务的层级关系
2. 展示主任务的子任务完成进度
3. 保持界面简洁，不增加过多视觉负担
4. 已完成的任务应有视觉衰减效果

## 设计决策

| 项目 | 决策 | 理由 |
|------|------|------|
| 视觉风格 | 缩进 + 虚线边框 | 层级清晰但不突兀，空间利用合理 |
| 折叠功能 | 始终展开 | 当前任务规模不大，无需折叠节省空间 |
| 进度显示 | 主任务显示子任务完成进度 (n/m) | 一目了然，便于追踪整体进度 |
| 嵌套深度 | 两级（主任务 + 子任务） | 满足当前需求，实现简单 |
| 已完成样式 | 已完成子任务变暗显示 | 与正在执行的任务形成对比，突出活跃任务 |

## 视觉效果

```
Tasks
● 分析用户需求 (2/3)
  │ ├─ ✓ 解析意图
  │ ├─ ✓ 提取实体
  │ └─ ● 生成查询计划

✓ 执行检索 (3/3)           ← 已完成主任务变暗
  │ ├─ ✓ 向量搜索
  │ ├─ ✓ 关键词匹配
  │ └─ ✓ 结果合并

✗ 生成响应
    └─ ✗ 格式化输出 API超时
```

### 样式规范

| 元素 | 样式 |
|------|------|
| 主任务 | 加粗显示 |
| 子任务容器 | 左侧虚线边框 (`border-left: 1px dashed #6272a4`) |
| 子任务缩进 | 16px (`padding-left: 16px`) |
| 已完成任务 | 颜色变为暗灰色 `#6272a4` |
| 进度显示 | 主任务名称后追加 `(completed/total)` |

### 状态图标

沿用现有设计：

| 状态 | 图标 | 颜色 |
|------|------|------|
| Pending | ○ | DarkGray |
| Running | ● | Yellow |
| Waiting | ○ | Cyan |
| Done | ✓ | Green |
| Failed | ✗ | Red |

## 实现要点

### 数据结构变更

`TaskState` 需新增字段：

```rust
pub struct TaskState {
    pub id: uuid::Uuid,
    pub name: String,
    pub status: TaskStatusKind,
    pub result: Option<String>,
    pub parent_id: Option<uuid::Uuid>,
    // 新增字段
    pub subtask_count: u32,      // 子任务总数
    pub completed_count: u32,    // 已完成子任务数
}
```

### 渲染逻辑

1. 按 `parent_id` 分组：
   - `parent_id = None` 为主任务
   - `parent_id = Some(id)` 为子任务

2. 渲染顺序：
   - 遍历主任务列表
   - 对每个主任务，渲染其所有子任务（缩进显示）

3. 样式规则：
   - 主任务：名称加粗，追加进度 `(n/m)`
   - 子任务：缩进 16px，左侧虚线边框
   - 已完成：整体颜色变暗

### 代码变更范围

1. `src/tui/app.rs` - TaskState 结构体新增字段
2. `src/tui/status.rs` - StatusPanel 渲染逻辑重构
3. `src/tui/mod.rs` - EngineEvent::TaskStatusChanged 处理逻辑更新（填充 subtask_count）

## 边界情况

| 场景 | 处理方式 |
|------|----------|
| 主任务无子任务 | 不显示进度，正常渲染 |
| 子任务先于主任务到达 | 子任务暂存，待主任务到达后关联 |
| 任务列表为空 | 显示空状态提示 |
| 子任务数量动态变化 | 实时更新进度显示 |

## 不在范围内

- 折叠/展开功能
- 三级及更深嵌套
- 任务详情展开面板
- 任务筛选/搜索

## 验收标准

1. 主任务和子任务层级关系清晰可辨
2. 主任务显示正确的子任务进度
3. 已完成任务视觉变暗
4. 不影响现有功能（Agent 显示、审批流程等）
5. 性能无明显下降

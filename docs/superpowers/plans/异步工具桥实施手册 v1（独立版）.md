## 第一章 背景与问题

与 agent 对话的用户，在 agent 执行 shell 命令期间会遇到整个助手冻结：消息不进来、定时器不响、其他任务停摆，直到命令退出或超时（最长 300 秒）才恢复。

根因不在某个工具的 bug，而在执行模型：工具在 ECS schedule 线程内同步执行，`shell_exec` 的阻塞轮询循环（`try_wait` + `sleep(10ms)`）直接把一帧拉长到秒级。「不堵 ECS」目前只靠工具作者自觉，架构本身允许任何工具堵死调度循环——每新增一个工具，这条腐化通道就继续生长。

与此同时，agent 想管理自己创建的动态定时任务（查看列表、删除），现有工具集完全没有这个能力。

代码库中已有一个被验证过的解法：LLM 调用早就走异步桥——`agent_execution_system` 收到请求后 `runtime.0.spawn` 扔给 tokio、当帧返回，结果经 mpsc 通道回传，由 `ingest_execution_results_system` 落地。**工具是唯一的同步孤岛。** 本改造把这座桥从 LLM 特例扩展为工具全域的构造。

## 第二章 目标与范围

### 目标

1. 所有工具请求统一走「dispatch 挂起 → tokio worker 异步执行 → 通道回传 → ingest 落地」，同步工具退化为「恰好很快完成的异步调用」。「不堵 ECS」从约定升级为构造。
2. 新增两个定时任务管理工具作为桥的第一批乘客：`list_scheduled_tasks`（纯读 pilot）与 `delete_scheduled_task`（首个写路径客户）。
3. 用户可感知的变化：shell 命令执行期间 agent 持续响应；任何工具调用最终恰好收到一个结果（含失联兜底）；LLM 可自查自删定时任务。代价是每个工具调用增加约一帧延迟（默认轮询间隔 16ms，可忽略）。

### 范围内

- 异步桥全套零件：owned 上下文、挂起实体、在飞标记、通道端对、异步 dispatch、ingest、sweeper、效果枚举、通用 commit。
- `list_scheduled_tasks` / `delete_scheduled_task` 两个新工具（作用域锁定**动态**定时任务）。
- shell_exec 迁移（含 CancellationToken 取消路径）。
- Rhai 插件 `spawn_blocking` 包裹（插件 API 不改）。
- 纯计算快工具（Direct 类）批量迁移。

### 范围外

- worker 池背压：mpsc 无界通道的 OOM 风险留作开放问题，pilot 实测后定（见 Task 8 背压实验与第十八章）。
- `triggers.toml` 静态 cron 路由的 list/delete 工具：将来另起一组，不混进这两个名字。
- 每工具 +1 帧延迟的进一步调优（默认 16ms 可忽略，用户可感再降）。
- 四类本已跨帧工具（wait_tasks / chat_with_agent / Confirm / channel_send）：天然合规，不动。

## 第三章 总体架构

### 3.1 执行模型

```
LLM tool-calling loop
   │  spawn ToolExecutionRequestMessage（含 tool_call_id，pending 登记先于任何结果落地）
   ▼
async_tool_dispatch_system（Frame N）
   │  认领 kind()==Async 的请求 → 挂起现场一次性做齐三件事：
   │    ① 调 max_duration 钩子算 sweeper 超时（std→chrono 转换只在这里做一次）
   │    ② 克隆 owned 只读快照（worker 零 ECS 接触）
   │    ③ 请求实体原地改造：摘请求消息 → 挂 ToolRequestPending + InFlightToolCall
   │  runtime.0.spawn(worker) —— worker 持 sender，catch_unwind 兜底 panic
   ▼
tokio worker（schedule 线程之外）
   │  纯函数式计算：吃 owned 快照，吐 ToolWorkerOutput（值或声明式效果）
   │  业务超时由 worker 侧 tokio::time::timeout 管（shell_exec 沿用既有三层链）
   ▼  sender.send(ToolAsyncResult)
ingest_tool_results_system（Frame N+k）—— 全桥唯一结果落地点
   │  try_recv 排空通道：
   │    Completed：挂起实体在 → spawn ToolExecutionResultMessage + despawn 挂起实体
   │               挂起实体不在 → drop + warn（晚到的重复结果）
   │    Effect：spawn ToolEffectPending，挂起实体保留（等 commit 回送最终结果）
   ▼
既有 barrier / restore（一行不改）
   │  pending_tool_call_ids 收齐 → 清空 → restore_task_after_tool 恢复任务续跑
   ▼
sweep_inflight_tool_calls（Maintenance set，兜底）
   超时 → claim 语义：发 error 结果入通道 + 摘除 InFlightToolCall（不 despawn）
   → error 流经 ingest 单点落地；worker 晚到的结果再进 ingest 时实体已没，drop
```

写路径（delete）多走一段：worker 吐声明式效果 → ingest 分流 spawn `ToolEffectPending` → `commit_tool_effects_system`（exclusive system）经 `update_scheduler_state` 双资源入口落账 → 把最终结果（含 `existed` 真相）送回通道 → ingest 下一帧落地。**结果落地仍是单点。**

### 3.2 六条架构不变量

1. **统一异步**：所有工具走同一座桥。回复协议不变——统一回复载体仍是结果消息实体，接受任何系统、任何帧 spawn 的结果。
2. **快照进、效果出**：worker 纯函数式吃 owned 快照、零 ECS 接触；写操作不在 worker 碰状态，只返回声明式效果，由 apply 阶段经既有的原子提交路径落账。
3. **compute / apply 切分**：worker 只做 compute（I/O、轮询、格式化）；改状态全部在 ECS 侧 apply 阶段。orchestrator 的工具动作处理逐 arm 按此切分。
4. **双账本单一修改入口**：SchedulerState + ScheduledTaskRegistry 的一切修改走 `update_scheduler_state` 单一入口，watch 只广播一次。
5. **结果落地单点 + exactly-once**：`ToolExecutionResultMessage` 只能由 ingest 产生；任何失联路径（panic / 超时 / 通道断开）最终恰好落地一条结果，由「挂起实体是否还在」唯一裁决。
6. **双超时分层**：业务超时在 worker 侧，sweeper 超时由 `max_duration` 注册钩推导且恒大于业务超时——间距由构造保证，不靠工具作者自觉。

### 3.3 零件清单

**新增零件（9 件）：**

| 零件 | 说明 |
|------|------|
| 挂起请求实体组件 `ToolRequestPending` | 携带 tool_call_id、tool_name、`Arc<AgentExecutionRequest>`（重建结果消息的字段来源） |
| 在飞标记组件 `InFlightToolCall` | `started_at + timeout`，sweeper 扫描对象；claim 时摘除 |
| 工具通道端对 `ToolResultSender/Receiver` | mpsc unbounded；dispatch/worker 持 sender，ingest 持 receiver |
| 异步 dispatch system | park 请求实体 + spawn worker；排在 sync dispatch 之前，只认领 Async |
| ingest system | 结果落地单点；Effect payload 分流 |
| sweeper system（Maintenance set） | 超时 claim：发 error 入通道 + 摘在飞标记 |
| `max_duration` 注册钩 | 挂 `BuiltinTool` trait，缺省返回全局 `tool_inflight_timeout_secs`（300s） |
| 声明式效果枚举 `ToolEffect` | worker 与 commit 系统之间的写路径契约 |
| 通用 commit system | exclusive system 形态，写效果的唯一应用点 |

**复用零件（4 件）：** LLM 执行桥的 ingest 模式（照抄模板）；tokio Runtime handle（既有 `AsyncRuntime` 资源）；Clock 资源与假时钟测试风格（既有）；待回结果登记 + 恢复 barrier（一行不改——统一异步后 barrier 第一次真正开始等待）。

## 第四章 设计决策（含理由）

以下决策已全部定案，理由内联，实施时直接遵循。

### D1 统一异步，不做外科手术

只把 shell_exec 异步化成本最小，但「新工具可能堵死 ECS」的通道还在，腐化继续长。统一异步后「不堵 ECS」从约定变成构造，执行桥照抄已验证的 LLM 路径；主要工作量在 ToolContext owned 化与工具动作的阶段切分。

### D2 快照进、效果出（snapshot-in / effect-out）

worker 跨帧存活，不能再借用 ECS 现场。dispatch 挂起时（此刻仍有 Res 只读访问）把工具需要的只读数据克隆进 owned 上下文，worker 纯函数式计算；写操作只返回声明式效果，apply 阶段经 `update_scheduler_state` 落账——双账本不变量一行不动。备选「Arc 句柄注入」（worker 直接读写共享状态）会破坏单一修改入口、把锁竞争引入 worker 池，否决。

**边界**：`original_request` / `task_id` / `agent_id` **不属于 worker 上下文**——它们由挂起实体携带，供 ingest/restore 重建结果消息；`OwnedToolContext` 只装 worker 干活需要的东西（只读快照 + 全局配置）。

### D3 失联清扫放在 ECS 侧：挂起实体 + sweeper

worker 侧的 `timeout + catch_unwind` 只是快速失败路径；任何逃脱 catch 的路径（abort、spawn_blocking 传播缝隙、未来新工具忘了包 timeout）都会让 barrier 静默挂死。兜底必须也是构造：dispatch 挂起时保留请求实体并挂 `InFlightToolCall{started_at, timeout}`（照抄确认机制的 park 先例——请求实体挂起等待、恢复后注销）；sweeper 扫在飞标记，超时补 error。附带红利：在飞调用在 ECS 里有实体足迹，排查时一眼可见。

### D4 sweeper 用 claim 语义，不 despawn

sweeper 超时后只做两件事：①把 error 结果发进通道；②摘除该实体的 `InFlightToolCall` 组件（claim——后续帧不再重复扫它）。**不 despawn 挂起实体、不落地结果。** 原因：ingest 以「挂起实体是否存在」去重——若 sweeper 发完 error 就 despawn，它自己刚发的 error 流到 ingest 时会因实体已没而被 drop，barrier 永远等不到结果。claim 语义下，sweeper 的 error 到 ingest 时实体仍在、正常落地 + despawn；worker 晚到的成功结果再进 ingest 时实体已没，drop + warn。落地与 despawn 全桥只有 ingest 一个点，exactly-once 闭合。

### D5 双超时分层 + max_duration 注册钩

- 业务超时留 worker 侧：`tokio::time::timeout` 包执行；shell_exec 沿用既有 per-call `timeout_secs` 三层链（入参 → 全局默认 → stop 超时），一行不改。
- sweeper 超时独立成链：工具注册时声明 `max_duration(&args) -> Duration` 钩子，缺省实现返回全局配置 `tool_inflight_timeout_secs`（新增，默认 300s，对齐既有 wait_tasks 超时量级）；shell_exec 覆盖该钩，读 per-call `timeout_secs` 加 30s margin。
- 「sweeper 超时 > 业务超时」由构造保证（钩子在业务值上加 margin）。若两者相等或更小，worker 正要正常回 error 时 sweeper 先补一条同 id 失联 error——barrier 收到两条结果，exactly-once 破功。
- 钩子调用现场是 **dispatch 挂起时**（算出 per-call timeout 写进在飞标记），sweeper 零策略只比对。

### D6 时间源：chrono 一贯到底 + 测试假时钟

`Clock` 资源是 `Clock(pub DateTime<Utc>)`，因此 `InFlightToolCall.started_at: DateTime<Utc>`、`timeout: chrono::Duration`，sweeper 用 `clock.0.signed_duration_since(...)` 判断，不新增任何时间资源、不动现有 Clock 消费方。std→chrono 的转换只在 dispatch 挂起现场做一次（`chrono::Duration::from_std`）。测试注入假时钟直接推进，与仓内全部现有时间相关测试同风格。**禁止 `Utc::now()` 出现在任何测试体**——测试里一切「现在」都来自 `world.resource::<Clock>().0`，否则 sweeper 测试必 flaky。

### D7 ToolContext 双轨改造

pilot 期新旧并存：上桥工具吃 `OwnedToolContext`，其余工具继续用 `ToolContext<'a>` 一行不动；随迁移推进 owned 版逐步接管，borrowed 版在 Phase 7 收尾退役。一步到位全仓重构违背「pilot 小步验证」的初衷，否决。

### D8 Sync/Async 标记挂在工具本体

路由发生在 execute **之前**，标记必须挂工具本体：`BuiltinTool::kind() -> ToolActionKind`，缺省 `Sync`（现有工具零改动），上桥工具 override 成 `Async`。dispatch 查到 executor 后读 `kind()` 分流，类型安全。标在输出枚举上拿不到路由时机，标在注册点旁路元数据则忘调就静默走同步路径，均否决。

### D9 max_duration 钩子挂 BuiltinTool trait

与 trait 三件套（kind / max_duration / run_async）同处声明，缺省实现返回全局配置。独立子 trait 方案需要 downcast 且事实上只有 shell_exec 会实现，否决。`run_async` 必须是 trait 方法而非自由函数——dispatch 才能泛型路由；缺省实现返回 `InternalState` 错误，Sync 工具误入 worker 路径时快速失败、不静默。

### D10 update_scheduler_state 扩展为双资源签名

闭包签名改 `FnOnce(&mut SchedulerState, &mut ScheduledTaskRegistry)`，三段式（remove → 改 → watch send → insert）扩到两个资源，**watch send 必须在两个资源都改完之后发一次**。现有调用方机械改闭包形状即可。改资源结构的方案会牵动所有 Registry 外部访问点，与 pilot 小步验证冲突，否决。

### D11 list 的 join 策略：过滤不一致 + 必须 warn

双账本靠单一修改入口保证原子一致，「SchedulerState 有、Registry 无」本身就是一致性 bug——把这种中间态以 null 字段喂给 LLM 是把内部腐化外泄成幻觉素材。正确行为是过滤掉，**且过滤时必须打 warn 日志**（kind、两边账本计数）——静默过滤会把双账本漂移藏起来。

### D12 测试 harness 风格

统一用普通 `#[test]`，禁止 `#[tokio::test]`：harness 内置 multi-thread Runtime 作为 `AsyncRuntime` 资源插入 world，worker 任务 spawn 到它的线程上独立跑；同步测试体内需要等异步完成时轮询 `try_recv` 或用其 `block_on`——安全。反过来 `#[tokio::test]` 里再 `block_on` 会触发 runtime 嵌套 panic。harness 放共享 `tests/common` 模块，后续所有 Task 复用，禁止各 Task 自造 Runtime。跑 system 一律 `world.run_system_once(...)`（仓内既有先例）。

### D13 背压验收形式：实验 + 报告结论

CI 断言精确内存数必然 flaky，改为「背压实验 + 结论记录」：pilot 测试中持有 receiver 不跑 ingest、堆积 1000 条结果消息，观测进程 RSS 写进 pilot 报告；**「是否切换有界通道 + backpressure」是 pilot 退出判据之一，报告必须有明确结论（换/不换 + 理由）**。

### D14 插件超时：允许缺省，manifest 可覆盖

Rhai 插件**允许不填** `max_duration`，走全局默认 300s；插件 manifest 可选填 `timeout_secs` 覆盖，包裹器的 `max_duration()` 读它。缺省有兜底符合「不靠自觉」原则，与 D5 的缺省链一致。

### D15 迁移顺序

pilot（`list_scheduled_tasks`，最简纯读工具打通全链路——桥的所有新零件第一次承压时不扛最复杂的工具）→ shell_exec（根治腐化源头）→ Rhai 插件（spawn_blocking 包裹，API 面最大单独一批）→ 批量快工具（机械搬）→ commit 系统通用化 → 清理与文档。双轨期 Phase 7 收尾前**禁止新增 Sync 工具**。

## 第六章 全局约束

- 遵循 Conventional Commits；commit body 用中文；代码与测试名用英文。
- **TDD 红绿纪律**：每个 Step 先写「跑必败」的测试（红），再写最小实现翻绿，**一对红绿一次 commit**。禁止先实现后补测试。
- **测试风格**：一律 `#[test]`，禁止 `#[tokio::test]`（runtime 嵌套 panic）；异步等待用 harness 的 `block_on` / 轮询 `try_recv`；跑 system 一律 `world.run_system_once(...)`。
- **时间源唯一**：测试里一切「现在」都来自 `world.resource::<Clock>().0`，禁止 `Utc::now()` 出现在任何测试体。
- **双账本不变量**：SchedulerState + ScheduledTaskRegistry 的一切修改走 `update_scheduler_state(world, |state, registry| ...)` 单一入口，watch 只广播一次。
- **结果落地单点**：`ToolExecutionResultMessage` 只能由 ingest 产生（含 sweeper 兜底的 error——sweeper 只发通道 + claim，不落地）。
- **双轨期纪律**：`ToolActionKind` 缺省 `Sync`；Phase 7 收尾前禁止新增 Sync 工具。
- 效果枚举膨胀是有意的「慢动作」设计：每加一个写效果 = 枚举加一个变体 + commit 加一支 arm，不妥协、不接受绕过。

```rust
// tests/common/async_tool_bridge.rs
use std::sync::Arc;
use bevy_ecs::prelude::*;
use chrono::{DateTime, Utc};
use tokio::runtime::Runtime;
use tokio::sync::mpsc;

use harness::app::{AsyncRuntime, Clock};
use harness::domain::{ToolAsyncResult, ToolResultReceiver, ToolResultSender};

/// 建测试 World：真实 multi-thread Runtime + 假时钟（起点为真实 now，可推进）+ 工具结果通道。
pub fn setup_bridge_world() -> World {
    let mut world = World::new();

    let rt = Runtime::new().expect("create tokio runtime");
    world.insert_resource(AsyncRuntime(Arc::new(rt)));

    // 关键：起点用 Utc::now()，测试里一切"现在"都经 now(&world) 取，
    // 保证 started_at 与 sweeper 判定用同一时间源。
    world.insert_resource(Clock(Utc::now()));

    let (tx, rx) = mpsc::unbounded_channel::<ToolAsyncResult>();
    world.insert_resource(ToolResultSender(tx));
    world.insert_resource(ToolResultReceiver(rx));

    world
}

/// 测试内唯一的"现在"。
pub fn now(world: &World) -> DateTime<Utc> {
    world.resource::<Clock>().0
}

/// 推进假时钟（sweeper 超时测试用）。
pub fn advance_clock(world: &mut World, secs: i64) {
    let mut clock = world.resource_mut::<Clock>();
    clock.0 += chrono::Duration::seconds(secs);
}

/// 轮询通道等一条结果（同步测试体内等异步 worker）。
pub fn wait_for_tool_result(world: &mut World, timeout_ms: u64) -> Option<ToolAsyncResult> {
    let start = std::time::Instant::now();
    loop {
        {
            let mut receiver = world.resource_mut::<ToolResultReceiver>();
            if let Ok(result) = receiver.0.try_recv() {
                return Some(result);
            }
        }
        if start.elapsed().as_millis() >= timeout_ms as u128 {
            return None;
        }
        std::thread::sleep(std::time::Duration::from_millis(1));
    }
}
```

```rust
/// 工具执行模式：双轨期 dispatch 分流依据。
#[derive(Debug, Clone, Copy, PartialEq, Eq, Default)]
pub enum ToolActionKind {
    /// 同步执行（原有路径，dispatch 现场直执）
    #[default]
    Sync,
    /// 异步执行（经异步桥：挂起 → worker → 通道 → ingest）
    Async,
}

/// worker 的执行产出：要么是给 LLM 的最终值，要么是声明式写效果（交 commit 系统落账）。
#[derive(Debug, Clone)]
pub enum ToolWorkerOutput {
    /// 直接结果（纯读/纯计算工具）
    Value(serde_json::Value),
    /// 声明式效果（写路径工具，由 commit_tool_effects_system 应用）
    Effect(crate::domain::ToolEffect),
}

/// 异步工具执行的 Future 形态。
pub type ToolFuture =
    std::pin::Pin<Box<dyn std::future::Future<Output = Result<ToolWorkerOutput, ToolError>> + Send>>;

pub trait BuiltinTool: Send + Sync + 'static {
    fn name(&self) -> &str;

    /// 执行模式，缺省 Sync（现有工具零改动）。
    fn kind(&self) -> ToolActionKind {
        ToolActionKind::Sync
    }

    /// sweeper 超时推导钩子。缺省返回全局配置；shell_exec 等 override 为业务超时 + margin。
    /// 调用现场是 dispatch 挂起时，不在 worker 内。
    fn max_duration(
        &self,
        _input: &serde_json::Value,
        tool_inflight_timeout_secs: u64,
    ) -> std::time::Duration {
        std::time::Duration::from_secs(tool_inflight_timeout_secs)
    }

    /// 异步执行入口。仅 kind()==Async 的工具需要 override；
    /// 缺省实现返回 InternalState 错误——Sync 工具误入 worker 路径时快速失败，不静默。
    fn run_async(&self, _input: serde_json::Value, _ctx: OwnedToolContext) -> ToolFuture {
        Box::pin(async {
            Err(ToolError::InternalState(
                "tool does not implement run_async (not migrated)".to_string(),
            ))
        })
    }

    fn execute(
        &self,
        input: &serde_json::Value,
        ctx: &ToolContext,
    ) -> Result<ToolAction, ToolError>;
}
```

```rust
//! 异步工具桥领域类型
//!
//! 结果落地单点原则：ToolExecutionResultMessage 只能由 ingest 产生；
//! sweeper 只发通道 + claim（摘除 InFlightToolCall），不落地不 despawn。

use std::sync::Arc;

use bevy_ecs::prelude::*;
use chrono::{DateTime, Duration as ChronoDuration, Utc};

use crate::domain::{AgentExecutionRequest, ChannelId, ToolError};
use crate::triggers::scheduled_task::ScheduleSpec;

// ============ 通道消息 ============

/// worker 回传的 payload：最终值（含错误）或声明式效果。
#[derive(Debug, Clone)]
pub enum ToolWorkerPayload {
    /// 工具执行完毕，直接可以喂给 LLM 的结果
    Completed(Result<serde_json::Value, ToolError>),
    /// 写路径效果，交 commit_tool_effects_system 应用后再产最终结果
    Effect(ToolEffect),
}

/// worker → ECS 的通道消息。
#[derive(Debug, Clone)]
pub struct ToolAsyncResult {
    /// LLM Tool Call ID（barrier 关联键）
    pub tool_call_id: String,
    pub payload: ToolWorkerPayload,
}

impl ToolAsyncResult {
    pub fn completed(tool_call_id: impl Into<String>, result: Result<serde_json::Value, ToolError>) -> Self {
        Self { tool_call_id: tool_call_id.into(), payload: ToolWorkerPayload::Completed(result) }
    }

    pub fn effect(tool_call_id: impl Into<String>, effect: ToolEffect) -> Self {
        Self { tool_call_id: tool_call_id.into(), payload: ToolWorkerPayload::Effect(effect) }
    }
}

#[derive(Resource)]
pub struct ToolResultSender(pub tokio::sync::mpsc::UnboundedSender<ToolAsyncResult>);

#[derive(Resource)]
pub struct ToolResultReceiver(pub tokio::sync::mpsc::UnboundedReceiver<ToolAsyncResult>);

// ============ 挂起实体与在飞标记 ============

/// 挂起的工具请求。dispatch 创建、ingest despawn。
/// original_request 用 Arc 共享：ingest 重建结果消息时零克隆读取。
#[derive(Component, Clone)]
pub struct ToolRequestPending {
    pub tool_call_id: String,
    pub tool_name: String,
    /// 原始请求（重建 ToolExecutionResultMessage 的完整字段来源）
```

**设计要点：**

1. **独立 system，不开进 `tool_dispatch_system`**——后者已 16+ 参数靠 tuple 合并压着 Bevy 上限。新 system 在 schedule 中排在 `tool_dispatch_system` **之前**运行：它只认领 `executor.kind() == Async` 的请求实体并原地改造（移除 `ToolExecutionRequestMessage`、挂上 `ToolRequestPending + InFlightToolCall`）；Sync 请求原样留给后面的 `tool_dispatch_system`，双轨分流零干扰。
2. **worker 模板照抄 LLM 桥**（`execution.rs:72-100`）：`runtime.0.spawn(async move { ... sender.send(...) })`。
3. **挂起现场一次性算齐**：`max_duration` 钩子调用、std→chrono Duration 转换、快照克隆，全部发生在 dispatch（此刻还有 Res 只读访问）。
4. **权限/确认**：pilot 工具（list/delete）不需 Confirm；本 system 只做「工具存在 + executor 存在」检查，权限校验仍由调用链上游与 Sync 路径既有逻辑各管各的。带 `pending_confirmation_id` 的请求直接跳过（Confirm 路径先行）。若未来 Async 工具需要 Confirm，确认通过后再进本 system——park 先例天然兼容，不在本文档展开。

```rust
//! 异步工具 dispatch：把 kind==Async 的工具请求原地改造为挂起实体，
//! 并把执行投给 tokio worker。结果经 ToolResultSender 通道回传，
//! 由 ingest_tool_results_system 落地。

use crate::prelude::*;
use tracing::{debug, warn};

use crate::{
    app::{AsyncRuntime, Clock, HarnessSettings},
    domain::{
        BuiltinToolExecutors, InFlightToolCall, OwnedToolContext, ToolActionKind,
        ToolAsyncResult, ToolExecutionRequestMessage, ToolRequestPending, ToolResultSender,
    },
    triggers::scheduled_task::{ScheduledTaskRegistry, SchedulerState},
};

use super::ingest_tool_results::build_scheduler_snapshot;

/// 异步工具 dispatch system。排在 tool_dispatch_system 之前运行：
/// 只认领 kind()==Async 的请求，Sync 请求原样留给旧路径。
pub fn async_tool_dispatch_system(
    mut commands: Commands,
    runtime: Res<AsyncRuntime>,
    clock: Res<Clock>,
    settings: Res<HarnessSettings>,
    executors: Res<BuiltinToolExecutors>,
    sender: Res<ToolResultSender>,
    scheduler_state: Option<Res<SchedulerState>>,
    registry: Option<Res<ScheduledTaskRegistry>>,
    requests: Query<(Entity, &ToolExecutionRequestMessage)>,
) {
    for (entity, request) in &requests {
        // 等待确认的请求不归这里管（Confirm 路径先行）
        if request.pending_confirmation_id.is_some() {
            continue;
        }

        let Some(executor) = executors.get(&request.tool_name) else {
            continue; // 未知工具留给 sync 路径统一报 NotFound
        };
        if executor.kind() != ToolActionKind::Async {
            continue; // Sync 工具走旧路径
        }

        let tool_call_id = request
            .tool_call_id
            .clone()
            .unwrap_or_else(|| uuid::Uuid::new_v4().to_string());
        let tool_name = request.tool_name.clone();
        let input = request.tool_input.clone();

        // 挂起现场：算 sweeper 超时（钩子在此刻调用，不在 worker 内）
        // 注：HarnessSettings 是 HarnessConfig 的新类型 Resource，字段经 .0 访问
        let timeout_std = executor.max_duration(&input, settings.0.tool_inflight_timeout_secs);
        let timeout = chrono::Duration::from_std(timeout_std)
            .unwrap_or_else(|_| chrono::Duration::seconds(settings.0.tool_inflight_timeout_secs as i64));

        // 挂起现场：克隆 owned 快照（worker 零 ECS 接触）
        let owned_ctx = OwnedToolContext {
            scheduler_state: scheduler_state.as_deref().map(build_scheduler_snapshot).map(std::sync::Arc::new),
            registry: registry.as_deref().map(build_registry_snapshot).map(std::sync::Arc::new),
            tool_inflight_timeout_secs: settings.0.tool_inflight_timeout_secs,
        };

        // 请求实体原地改造：摘请求消息 → 挂 Pending + InFlight
        let original_request = std::sync::Arc::new(request.request.clone());
        commands.entity(entity).remove::<ToolExecutionRequestMessage>();
        commands.entity(entity).insert((
            ToolRequestPending {
                tool_call_id: tool_call_id.clone(),
                tool_name: tool_name.clone(),
                original_request,
            },
            InFlightToolCall {
                started_at: clock.0,
                timeout,
            },
        ));

        // 投 worker（照抄 LLM 桥模板：runtime.0.spawn + 通道回传）
        let tx = sender.0.clone();
        let call_id = tool_call_id.clone();
        let future = executor.run_async(input, owned_ctx);
        runtime.0.spawn(async move {
            use futures_util::FutureExt;
            // catch_unwind：worker panic 也合成 error 结果回传（快速失败路径；
            // 兜底仍靠 sweeper——发送失败/通道断开时 sweeper claim 补 error）
            let outcome = std::panic::AssertUnwindSafe(future).catch_unwind().await;
            let payload = match outcome {
                Ok(Ok(output)) => match output {
                    crate::domain::ToolWorkerOutput::Value(v) => {
                        crate::domain::ToolWorkerPayload::Completed(Ok(v))
                    }
                    crate::domain::ToolWorkerOutput::Effect(effect) => {
                        crate::domain::ToolWorkerPayload::Effect(effect)
                    }
                },
                Ok(Err(e)) => crate::domain::ToolWorkerPayload::Completed(Err(e)),
                Err(_) => crate::domain::ToolWorkerPayload::Completed(Err(
                    crate::domain::ToolError::ExecutionFailed("worker panicked".to_string()),
                )),
            };
            let _ = tx.send(ToolAsyncResult { tool_call_id: call_id, payload });
        });

        debug!(
            event = "AsyncToolDispatched",
            tool_call_id = %tool_call_id,
            tool_name = %tool_name,
            timeout_secs = timeout.num_seconds(),
            "async tool parked and worker spawned"
        );
    }
}

fn build_registry_snapshot(
    registry: &ScheduledTaskRegistry,
) -> crate::domain::ScheduledTaskRegistrySnapshot {
    crate::domain::ScheduledTaskRegistrySnapshot {
        tasks: registry
            .iter()
            .map(|(kind, info)| {
                (
                    kind.clone(),
                    crate::domain::ScheduledTaskInfoSnapshot {
                        content: info.content.clone(),
                        output_channel: info.output_channel.clone(),
                        is_once: info.is_once,
                    },
                )
            })
            .collect(),
    }
}
```

```rust
//! 工具结果 ingest：全桥唯一的结果落地点。

use crate::prelude::*;
use tracing::warn;

use crate::domain::{
    AgentExecutionOutput, AgentExecutionResult, ExecutionError, OutputContent, ToolAsyncResult,
    ToolEffectPending, ToolRequestPending, ToolResultReceiver, ToolReturnedHookPending,
    ToolExecutionResultMessage, ToolWorkerPayload,
};
use crate::triggers::scheduled_task::SchedulerState;

/// ingest system：try_recv 排空通道。
/// - Completed：挂起实体在 → 落地结果 + despawn；不在 → drop + warn（重复/迟到）
/// - Effect：spawn ToolEffectPending，挂起实体保留（等 commit 回送最终结果）
pub fn ingest_tool_results_system(
    mut commands: Commands,
    mut receiver: ResMut<ToolResultReceiver>,
    pending: Query<(Entity, &ToolRequestPending)>,
) {
    while let Ok(result) = receiver.0.try_recv() {
        match result.payload {
            ToolWorkerPayload::Completed(output) => {
                let Some((entity, pending)) =
                    pending.iter().find(|(_, p)| p.tool_call_id == result.tool_call_id)
                else {
                    warn!(
                        event = "ToolResultDroppedNoPending",
                        tool_call_id = %result.tool_call_id,
                        "result arrived but pending entity gone (sweeper claimed or duplicate); dropping"
                    );
                    continue;
                };
                spawn_tool_result_message(&mut commands, pending, output);
                commands.entity(entity).despawn();
            }
            ToolWorkerPayload::Effect(effect) => {
                // 挂起实体必须还在，否则效果来源不可考；不在则丢弃并告警
                if !pending.iter().any(|(_, p)| p.tool_call_id == result.tool_call_id) {
                    warn!(
                        event = "ToolEffectDroppedNoPending",
                        tool_call_id = %result.tool_call_id,
                        "effect arrived but pending entity gone; dropping"
                    );
                    continue;
                }
                commands.spawn(ToolEffectPending {
                    tool_call_id: result.tool_call_id.clone(),
                    effect,
                });
            }
        }
    }
}

/// 由挂起实体携带的 original_request 重建完整结果消息（9 字段对齐 execution.rs:102）。
pub(crate) fn spawn_tool_result_message(
    commands: &mut Commands,
    pending: &ToolRequestPending,
    output: Result<serde_json::Value, crate::domain::ToolError>,
) {
    let req = &pending.original_request;
    let execution_result = AgentExecutionResult {
        task_id: req.task_id,
        agent_id: req.agent_id,
        request_kind: req.request_kind.clone(),
        result: match &output {
            Ok(value) => Ok(AgentExecutionOutput {
                content: OutputContent::Text(
                    serde_json::to_string(value).unwrap_or_else(|_| "{}".to_string()),
                ),
                reasoning_content: None,
            }),
            Err(e) => Err(ExecutionError::Unknown(e.to_string())),
        },
        prompt: req.prompt.clone(),
        system_prompt: req.system_prompt.clone(),
        tools: req.tools.clone(),
        reasoning_content: None,
        work_item_id: req.work_item_id,
    };

    commands.spawn((
        ToolExecutionResultMessage {
            result: execution_result,
            tool_name: pending.tool_name.clone(),
            tool_output: output,
            tool_call_id: Some(pending.tool_call_id.clone()),
            processed: false,
            original_tool_output: None,
        },
        ToolReturnedHookPending,
    ));
}
```

```rust
//! 失联清扫器：超时 claim —— 发 error 入通道 + 摘除 InFlightToolCall。
//! 不 despawn 挂起实体、不落地结果：落地与 despawn 只发生在 ingest。

use crate::prelude::*;
use tracing::warn;

use crate::{
    app::Clock,
    domain::{
        InFlightToolCall, ToolAsyncResult, ToolError, ToolRequestPending, ToolResultSender,
    },
};

pub fn sweep_inflight_tool_calls(
    mut commands: Commands,
    clock: Res<Clock>,
    sender: Res<ToolResultSender>,
    query: Query<(Entity, &ToolRequestPending, &InFlightToolCall)>,
) {
    let now = clock.0;

    for (entity, pending, in_flight) in &query {
        let elapsed = now.signed_duration_since(in_flight.started_at);
        if elapsed <= in_flight.timeout {
            continue;
        }

        warn!(
            event = "ToolCallSweepTimeout",
            tool_call_id = %pending.tool_call_id,
            tool_name = %pending.tool_name,
            timeout_secs = in_flight.timeout.num_seconds(),
            elapsed_secs = elapsed.num_seconds(),
            "tool call lost contact; claiming and sending error result"
        );

        let _ = sender.0.send(ToolAsyncResult::completed(
            pending.tool_call_id.clone(),
            Err(ToolError::Timeout(format!(
                "tool '{}' lost contact after {}s (sweeper)",
                pending.tool_name,
                elapsed.num_seconds()
            ))),
        ));

        // claim：摘除在飞标记，实体留给 ingest 落地后 despawn
        commands.entity(entity).remove::<InFlightToolCall>();
    }
}
```

```rust
// src/systems/tools/builtin/scheduled/list.rs
use tracing::warn;

use crate::domain::{
    BuiltinTool, OwnedToolContext, ToolAction, ToolActionKind, ToolContext, ToolError,
    ToolFuture, ToolWorkerOutput,
};
use crate::triggers::scheduled_task::compute_next_trigger;

pub struct ListScheduledTasksTool;

impl BuiltinTool for ListScheduledTasksTool {
    fn name(&self) -> &str {
        "list_scheduled_tasks"
    }

    fn kind(&self) -> ToolActionKind {
        ToolActionKind::Async
    }

    fn execute(&self, _: &serde_json::Value, _: &ToolContext) -> Result<ToolAction, ToolError> {
        // Async 工具不会走到这里（dispatch 按 kind 分流）；快速失败防误调
        Err(ToolError::InternalState(
            "list_scheduled_tasks is async-only".to_string(),
        ))
    }

    fn run_async(&self, _input: serde_json::Value, ctx: OwnedToolContext) -> ToolFuture {
        Box::pin(async move {
            let state = ctx.scheduler_state.ok_or_else(|| {
                ToolError::InternalState("scheduler snapshot missing".to_string())
            })?;
            let registry = ctx.registry.ok_or_else(|| {
                ToolError::InternalState("registry snapshot missing".to_string())
            })?;

            let mut tasks = Vec::new();
            for dt in &state.dynamic_tasks {
                let Some(info) = registry.tasks.get(&dt.kind) else {
                    // 过滤不一致项 + 必须 warn（双账本漂移的线上观测）
                    warn!(
                        event = "SchedulerLedgerInconsistency",
                        kind = %dt.kind,
                        scheduler_count = state.dynamic_tasks.len(),
                        registry_count = registry.tasks.len(),
                        "task in SchedulerState but not in Registry; filtered"
                    );
                    continue;
                };

                let mut entry = serde_json::json!({
                    "kind": dt.kind,
                    "content": info.content,
                    "output_channel": info.output_channel,
                    "is_once": info.is_once,
                    "created_at": dt.created_at.to_rfc3339(),
                });
                if let Some(next) = compute_next_trigger(&dt.schedule) {
                    entry["next_fire_time"] = serde_json::Value::String(next.to_rfc3339());
                }
                tasks.push(entry);
            }

            Ok(ToolWorkerOutput::Value(serde_json::json!({
                "tasks": tasks,
                "count": tasks.len(),
            })))
        })
    }
}
```

- [ ] **Step 2（绿）：实现 commit system（exclusive system 形态）**

`update_scheduler_state` 要 `&mut World`，因此本 system 用 **exclusive system** 形态（`fn(world: &mut World)`）——仓内处理「需要整 World 写权限」的既定手法，测试侧 `world.run_system_once(...)` 同样适用：

```rust
//! 通用效果提交：写效果的唯一应用点。
//! 每个效果 arm 必须经 update_scheduler_state 双资源入口落账；
//! 应用后把最终结果送回通道，由 ingest 落地。

use bevy_ecs::prelude::*;
use tracing::warn;

use crate::domain::{ToolAsyncResult, ToolEffect, ToolEffectPending, ToolError, ToolResultSender};
use crate::triggers::scheduled_task::update_scheduler_state;

/// exclusive system：直接拿 &mut World 调 update_scheduler_state。
/// 注册：与普通 system 混排，固定进 Maintenance set（commit → 下一帧 ingest 落地）。
pub fn commit_tool_effects_system(world: &mut World) {
    let mut to_apply = Vec::new();
    let mut q = world.query::<(Entity, &ToolEffectPending)>();
    for (e, p) in q.iter(world) {
        to_apply.push((e, p.tool_call_id.clone(), p.effect.clone()));
    }

    let sender = world.resource::<ToolResultSender>().0.clone();

    for (entity, call_id, effect) in to_apply {
        let output = apply_effect(world, &effect);
        let _ = sender.send(ToolAsyncResult::completed(call_id, output));
        world.entity_mut(entity).despawn();
    }
}

fn apply_effect(
    world: &mut World,
    effect: &ToolEffect,
) -> Result<serde_json::Value, ToolError> {
    match effect {
        ToolEffect::DeleteScheduledTask { kind } => {
            let mut existed = false;
            update_scheduler_state(world, |state, registry| {
                let before = state.dynamic_tasks().len();
                state.dynamic_tasks_mut().retain(|dt| dt.kind != *kind);
                let removed_from_state = state.dynamic_tasks().len() < before;
                let removed_from_registry = registry.remove(kind).is_some();
                existed = removed_from_state || removed_from_registry;
                if removed_from_state != removed_from_registry {
                    warn!(
                        event = "LedgerDriftOnDelete",
                        kind = %kind,
                        in_state = removed_from_state,
                        in_registry = removed_from_registry,
                        "delete removed from only one ledger"
                    );
                }
            });
            Ok(serde_json::json!({ "deleted": kind, "existed": existed }))
        }
    }
}
```

```rust
pub struct DeleteScheduledTaskTool;

        "delete_scheduled_task"

        ToolActionKind::Async
    }
```

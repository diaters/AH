# 单通道用户任务路由回归

> __状态：实现验证记录__
> 依据：已确认的单通道任务与进程生命周期规格；限制用户会话顶层任务，内部子任务仍可并行。

## 失败证据与修正

- 同帧十条输入原来创建十个用户任务；统一创建入口现在按完整 ChannelId 预留名额，后续正文进入该任务收件箱。
- `/btw` 原来绕过创建入口，在 Pending 用户任务旁再建顶层任务；现在提示先 `/finish`，空通道可创建新主题。
- `/finish` 与新正文同帧时，正文可能投递到即将结束的旧任务而丢失；外部输入序号与命令屏障现在保留 FIFO。
- `/finish` 的终态与 `/clear` 的实体移除都不再直接代表名额释放；实际在飞 worker、后台会话和子任务清理完成后才能新建。
- `ToolRequestPending` 在取消后仍可能存在，不能以 `InFlightToolCall` 标记消失作为清理确认。
- 异常多个用户根任务时显式报告冲突；不再按“第一条”或更新时间静默选择。
- 插件无父任务的创建经过同一入口；有父任务的内部创建保留并行和真实父子关系。

## 测试说明

新增同帧十条输入、`/btw`、命令先后顺序、`/finish` 和 `/clear` 清理确认回归。
前四项先得到行为失败，`/clear` 补测也先复现输入未被保留，再实现清理屏障。
历史测试中“多个任务选第一条或最新一条”以及“`/btw` 创建并行任务”的断言按已确认规格替换为冲突提示。

针对性验证覆盖多轮路由、跨通道隔离、运行中 steer、`/stop`、工具审批和 ask_user；
全量验证和独立审查结果由实施计划及对应 PR 记录。

旧的同通道并行用户回复用例改为两个定时任务共享输出通道，验证并行输出能力和不同任务 ID；
新用户任务限制没有影响仅输出型任务。同步、异步工具派发在启动前拒绝终态 owner 的排队请求。

## 独立规格审查后的修正

- 子任务仍可使用 `ask_user`；回答按唯一待答问题关联到原子任务工具调用，不能误作根任务 steer。
- `/finish`、`/clear` 及终态清理真正中止任务级 provider 请求，包括 Brain 请求；
  已请求中止的句柄保留到实际完成，关闭屏障据此等待，不以“发出 abort”替代“已完成”。
- 终态 Task 不再启动迟到的排队 provider 请求，迟到 Brain 决策也不能重新挂载派发。
- `/clear` 保留占用的同时显示 backend 清理错误原因，相同失败不按帧重复推送。
- 对应回归均先复现失败再修复；第一次完整验证在这些审查修正之前为 1465 项通过、7 项忽略，
  最终完整验证以合并所有修正后的记录为准。

## TUI 与外部输入顺序补齐

- 独立评审发现 TUI 入口没有附加 `InputSequence`，原有实体编号排序会受实体复用影响，
  不能保证正文与 `/finish` 的先后顺序。新增回归先复现 TUI 信号缺少序号。
- TUI 与外部线程输入现在共用实例级 `InputSequencer`，在创建 Signal 前分配单调序号，
  避免两个入口分别计数产生重复序号；序号继续随用户消息、创建消息和收件箱投递传播。
- 新增同通道混合入口连续两帧验证，断言序号不重复、不重置，并对应系统实际接收顺序。
  两入口同帧并发到达时，序号表示 ECS 接收次序，不推断外部设备的绝对发生时间。
